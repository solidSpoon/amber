# Amber 品牌与视觉

> 这份文档管"长什么样、叫什么"。产品是什么、给谁用，看 `PRODUCT.md`。
> 两者冲突时，产品定义优先——视觉永远服务于"这个东西是干什么的"。

---

## 一、名字

**Amber**，中文写"琥珀"。具体用的是**蓝珀**（Blue Amber）。

蓝珀是个真东西：多米尼加出的琥珀，平时看着是深青发黑的石头，光打进去才透出那层蓝——
它的蓝不是体色，是荧光。

选它有两个原因：

- **能说出产品在做什么。** 这台机器平时不动，AI 上去跑一遍，记录才亮起来。
- **不和货架上的东西撞色。** 同类工具清一色靛蓝、紫、暖褐，深青蓝是空的。

## 二、标志

一块树脂切片里封着一个东西。

| 元素 | 是什么 | 不要变成 |
| --- | --- | --- |
| 圆角矩形 | 整块琥珀切片（不是"底板"） | 底板 + 里面再放一块石头（会变成靶心） |
| 一条带弧的切割线 | 被切开的那一刀 | 直线（读起来像纸被折过）；大弧（变成图形手势） |
| 一个偏心的深色点 | 被封住的那一刻 | 回到板心（立刻退回靶心） |

三条硬规则，改图形时别破：

1. **只有一层形体。** 图标本身就是琥珀，不是"容器里装着一个图标"。
2. **内含物必须偏心，且和底板不同形。** 底板是圆角方，内含物就用圆。
3. **只有两档琥珀色 + 一个深色。** 第三档（比如右下角切一小块暗面）在大尺寸是"面"，
   缩到 32px 就变成"缺了一角"。

另外不要加：气泡/杂点（像屏幕脏了）、渐变光球、投影、描边倒角。

## 三、色板

蓝珀（默认）：

| 名称 | 用途 | 色值 | oklch |
| --- | --- | --- | --- |
| board | 板子 / 界面主色 | `#1C5568` | `oklch(0.421 0.066 224)` |
| facet | 切面 / ring、图表首选色 | `#4E97AB` | `oklch(0.637 0.079 218)` |
| glint | 棱上的反光（只用在图标里） | `#C9EDF3` | `oklch(0.922 0.038 209)` |
| inclusion | 被封住的那一刻 | `#041A22` | `oklch(0.204 0.033 225)` |

界面用色的规矩（`web/src/styles.css`）：

- **只写语义 token**：`bg-background` / `text-muted-foreground` / `bg-primary`，
  不出现 `text-sky-600` 这类原始色值。换主题时靠改 token，不靠全仓库搜索替换。
- 中性色的 chroma 压在 **0.01 以内**，hue 统一在 205–228。
  再大一点整页就会"发绿"，看着像另一个产品。
- 暗色底不是纯黑，是带蓝的墨（`hue 228 / chroma 0.018`）；
  主色在暗色下换成浅青提亮，否则按钮文字读不出来。
- `success` / `warning` / `destructive` 只用于结果与告警，不参与品牌表达。
- **打底一律中性。** 页底 `oklch(0.984 0.002 220)`、侧栏 `0.968`、卡片纯白，
  chroma 全部 ≤ .004。整页刷青会变成另一个产品的气质，而且久看发灰。
- **青只做点缀**：logo、选中的导航项（`bg-primary/10 text-primary`）、主按钮、`--ring`。
  大面积（页面底、侧栏、卡片）碰都不要碰。
- 暗色同理：中性深灰 `oklch(0.205 0.004 230)`，卡片抬到 `0.245`，不用纯黑、也不刷蓝。
- 例外只有一处：**看板上的机器外壳**。那是拟物的铝，色值写死、不参与主题。

## 四、规格

macOS 应用图标（Big Sur 之后）：

```
画布   1024 × 1024
版心   824 × 824，居中，四边各留 100 安全边
圆角   r = 185.4（Apple 模板值；真身是超椭圆，圆角矩形是同尺寸下最接近的近似）
```

favicon 不单独画：`viewBox` 直接取版心 `100 100 824 824`，**一个坐标都不换算**。
早先人工除以 16 忘了减安全边，出过"大图是直线、小图是折线"的事故。

## 五、怎么生成

图形是代码画的，**不要手改生成物**：

```bash
make icons                               # 重新生成 SVG + 1024 位图
go run ./cmd/ambericon -palette amber    # 换回原色
go run ./cmd/ambericon -bow 0            # 切割线拉直（-38 是默认的弧度）
go run ./cmd/ambericon -palette green    # 备选色：green / indigo / slate
```

产出：

```
web/public/app-icon.svg       1024 画布，带安全边
web/public/amber.svg          favicon，取版心
web/public/app-icon-1024.png  位图，做 .icns 用
```

源：`cmd/ambericon/main.go`。形状参数（切割线两个落点、内含物位置、弯曲量 `cutBow`）
和配色（`palettes`）都在文件开头，改一个数就是另一版。

打 `.icns`：

```bash
cd web/public && mkdir -p Amber.iconset
for s in 16 32 128 256 512; do
  rsvg-convert -w $s      -h $s      app-icon.svg -o Amber.iconset/icon_${s}x${s}.png
  rsvg-convert -w $((s*2)) -h $((s*2)) app-icon.svg -o Amber.iconset/icon_${s}x${s}@2x.png
done
cp app-icon-1024.png Amber.iconset/icon_512x512@2x.png
iconutil -c icns Amber.iconset -o Amber.icns
```

## 六、用词

界面文案里不出现"测试"口气的词。这台东西的定位是**给 AI 用的一台机器**，
人只是事后看它跑了什么，不是来读测试报告、也不是来写用例的。

已经定下来的几条：

| 用 | 不用 | 为什么 |
| --- | --- | --- |
| 会话、步骤、一段 | —（保持通用） | 跟目的无关：AI 就是想用一下这台机器 |
| **记录** | 验收报告 | 报告是交付物，记录是它自己留下的 |
| **成立 / 不成立 / 看不出** | 通过 / 不通过 / 无法判定 | 只说看到了什么，不下判决 |
| **一次性机器** | 一次性测试机 | "测试"是我们替调用方加的限制 |
| `amber_start` / `amber_run` / `amber_capture` / `amber_stop` / `amber_list` / `amber_feedback` | `start_session` / `run` / … | 工具面统一前缀，一眼看出是这台机器提供的 |

接口层不动：`sessionId`、`reportUrl`、`verdict` 的 `pass/fail/inconclusive` 都保持原样，
只换人读的中文。改字段名会打断已经接好的调用方。
